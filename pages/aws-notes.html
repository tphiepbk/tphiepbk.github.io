AWS notes

Most AWS services are Regional. Learn which resources span Regions, which belong to one Region, and which live in a single Availability Zone.

Global, Regional, and zonal scope

Global scope

These resources span AWS Regions rather than being created separately in each Region. Global scope is within an AWS partition, such as standard commercial AWS.

  • IAM: users, groups, roles, and policies.
  • CloudFront: content delivery distributions.
  • Route 53: DNS hosted zones and records.
  • Global Accelerator: accelerators that route traffic to regional endpoints.

Memory aid: IAM + CloudFront + Route 53 + Global Accelerator.

Regional scope

You select a Region, such as ap-southeast-1 (Singapore). Resources in another Region are managed separately.

  • Compute: EC2, Lambda, ECS, EKS.
  • Storage: S3 buckets, EFS, EBS.
  • Databases: RDS, Aurora, DynamoDB, ElastiCache, Redshift.
  • Networking: VPC, Elastic Load Balancing, API Gateway.
  • Messaging: SQS, SNS, EventBridge.
  • Management and security: CloudWatch, CloudFormation stacks, KMS keys, Secrets Manager.

A Regional service can contain resources tied to one Availability Zone. Cross-Region features require their own configuration.

Common exam exceptions

  • S3 buckets are Regional: a console listing buckets across Regions does not make the buckets global. Data stays in its Region unless explicitly transferred or replicated.
  • WAF has both scopes: global for CloudFront; Regional for resources such as Application Load Balancers and API Gateway REST APIs.
  • STS has global and Regional endpoints: AWS recommends using Regional endpoints.
  • Route 53 features differ: DNS hosted zones are global, but Route 53 Resolver endpoints are Regional.

Check the specific resource or feature when scope matters; a service name alone does not always tell the whole story.

Availability Zone scope

A Region contains multiple Availability Zones (AZs). Some resources belong to exactly one AZ:

  • EC2 instance: runs in a specific AZ.
  • EBS volume: belongs to one AZ and attaches to instances in that AZ.
  • VPC subnet: belongs to one AZ; the VPC itself spans the Region.

Example: create a VPC in Singapore, then create subnets in two AZs to place workloads across them.
