What is cloud computing?

Understand the building blocks before choosing a service.

↑
IT foundations

A client requests a service across a network. Servers combine CPU, RAM, storage, and software; IP addresses identify interfaces, routers connect networks, switches connect devices, and DNS resolves names.

On-demand cloud

Provision resources through a service provider and pay for measured usage. Self-service, network access, pooled resources, elasticity, and metering distinguish cloud computing from simply owning remote servers.

Cloud economics

Exchange large upfront hardware purchases (CapEx) for operating expenditure (OpEx). Economies of scale, demand-based capacity, faster experimentation, less data-center work, and global reach are the core benefits.

Deployment models

Public cloud uses a provider’s infrastructure; private cloud serves one organization; hybrid combines on-premises and cloud resources. Choose according to control, integration, and residency needs.

Service models

IaaS provides infrastructure such as EC2; you manage the operating system and application. PaaS, such as Elastic Beanstalk, manages more of the platform. SaaS provides a finished application. Responsibility shifts as management moves to the provider.

Regions, AZs, and edge locations

A Region contains isolated Availability Zones (each with one or more data centers). Choose Regions by residency requirements, customer proximity, service availability, and cost. Edge locations support delivery near users; they are not interchangeable with Regions.

Global and regional scope

IAM and Route 53 are examples of global services. EC2 and RDS deployments are regional. S3 buckets live in a Region even though the console presents a global view.

Shared responsibility and acceptable use

AWS protects the infrastructure of the cloud. Customers protect their data, identities, and service configuration in the cloud. The precise split depends on the service. The acceptable-use policy governs permitted use.

Check your understandingIs elasticity the same as high availability?

No. Elasticity adjusts capacity to demand; high availability keeps a workload accessible despite failures.

Identity & Access Management

Decide who can do what, on which resources.

↑
Users and groups

An IAM user represents an identity in an account. Groups collect users with common permissions; groups do not contain other groups. Prefer federation and temporary credentials for routine access where possible.

Policies and least privilege

Policies describe allowed or denied actions on resources, optionally with conditions. Common fields include Effect, Action, Resource, and Condition; resource policies can name a Principal. Start with only the permissions the task needs.

Permission evaluation

Access starts implicitly denied. Applicable policies must permit it; explicit deny wins. Account guardrails and other policy types can further restrict access. A group policy is inherited by its members.

Passwords and MFA

Protect sign-in with a strong password policy and multi-factor authentication. MFA combines something you know with another factor such as an authenticator or hardware security key.

Console, CLI, and SDK

The console is a web interface; the CLI runs commands; SDKs let applications call AWS APIs. Programmatic credentials are sensitive. Do not embed or share access keys; use temporary credentials or workload roles.

Roles for services

An EC2 instance or Lambda function assumes a role to call other AWS services. Assign a role instead of storing a person’s access keys on the server.

Audit access

The IAM credentials report summarizes credential status across account users. Access Advisor shows service access information to help reduce unnecessary permissions.

Root account and responsibility

Protect root access with MFA and reserve it for tasks that require it. AWS operates IAM infrastructure; you manage identities, credentials, policies, and access reviews.

Check your understandingHow should an EC2 application access S3?

Attach an IAM role with the necessary S3 permissions to the instance; avoid hard-coded access keys.

Amazon EC2

Choose a virtual machine and a purchasing model that fit the workload.

↑
Instance families

General-purpose instances balance resources; compute-optimized instances suit CPU-heavy work; memory-optimized instances suit large working sets; storage-optimized instances suit intensive local I/O. Match the workload rather than buying the largest size.

Launch configuration

Choose an AMI, instance type, storage, network, security groups, and IAM role. User data can bootstrap software at first launch; scripts commonly run with elevated privileges.

Security groups

Stateful allow rules protect network interfaces. Return traffic for an allowed connection is permitted automatically. Reference CIDRs or other security groups; avoid opening administration ports to everyone.

Connections and ports

SSH commonly uses TCP 22, RDP 3389, HTTP 80, HTTPS 443, and FTP 21. EC2 Instance Connect supports managed SSH access. A connection timeout often suggests networking or firewall configuration; connection refusal may mean no service is listening.

On-Demand

Use without a long-term commitment for uncertain or short-lived demand. You pay for the resources you run according to the applicable billing model.

Reserved Instances and Savings Plans

Reserved Instances provide discounts tied to specified instance attributes; Standard and Convertible offer different flexibility. Savings Plans commit to an hourly spend for a term. Compute Savings Plans are broader than EC2 Instance Savings Plans.

Spot

Use spare capacity for interruptible work such as batch jobs or flexible processing. Design for interruption and retry; do not treat capacity as guaranteed.

Dedicated Hosts and Dedicated Instances

A Dedicated Host gives control over a physical server and can address host-bound licensing. Dedicated Instances isolate tenancy on hardware without the same placement and host visibility.

Capacity Reservations

Reserve capacity in a particular AZ. A capacity reservation alone is not a discount and can incur charges while unused; capacity assurance and billing discounts solve different problems.

Shared responsibility

AWS maintains facilities, physical hardware, and virtualization. You patch the guest OS, configure network access, secure application data, and maintain installed software.

Check your understandingWhich choice fits a batch job that can restart after interruption?

Spot capacity, with checkpointing or retries. A critical uninterrupted workload needs a different capacity strategy.

EC2 instance storage

Separate block storage, shared files, and temporary local disks.

↑
EBS volumes

Network-attached block storage for EC2, scoped to an Availability Zone. Provision capacity and performance. Data can outlive an instance, but the delete-on-termination setting determines whether a volume is deleted with it.

Snapshots and recovery

EBS snapshots back up volumes and enable restoration or copying to another AZ or Region. Snapshot Archive targets infrequent recovery; Recycle Bin retention rules can protect against accidental deletion. Plan application-consistent backups.

AMIs

An Amazon Machine Image packages launch information such as an OS and installed software. Create a reusable image from a configured instance; AMIs are regional and can be copied. Public, private, and Marketplace images serve different needs.

EC2 Image Builder

Automate building, testing, and distributing machine or container images. Image maintenance is an ongoing process, not a one-time copy.

Instance store

Local hardware storage provides fast I/O for caches, buffers, and scratch data. Data can disappear on stop, termination, or host failure; it must not be the only copy of durable information.

EFS and EFS-IA

EFS provides shared NFS files for Linux clients, with regional deployments spanning AZs. Lifecycle policies move infrequently accessed files to lower-cost tiers. Shared files differ from an EBS disk attached to a machine.

FSx

FSx provides managed file systems. Windows File Server supports SMB and Active Directory integration; Lustre targets high-performance computing and integrates with S3. The slides also identify NetApp ONTAP as an FSx option.

Storage responsibility

AWS runs the storage infrastructure. You choose encryption, permissions, backup policies, retention, and the right durability model for your data.

Check your understandingMany Linux servers need the same shared files. EBS or EFS?

EFS is the shared-file choice. EBS is block storage scoped to an AZ; it is not a general shared NFS file system.

Elastic Load Balancing & Auto Scaling

Spread traffic, replace failed instances, and match capacity to demand.

↑
Scale up or scale out

Vertical scaling increases one machine’s size; horizontal scaling adds machines. Elasticity adjusts capacity as demand changes. Agility is the speed of provisioning and experimentation.

High availability

Distribute the workload across AZs so one failure boundary does not take down the entire service. Adding servers in a single AZ improves capacity but does not protect against losing that AZ.

Elastic Load Balancing

Provides a managed entry point, distributes requests, and checks target health. TLS termination and multi-AZ deployment reduce application and operations work.

Load balancer types

Application Load Balancer routes HTTP/HTTPS traffic at layer 7. Network Load Balancer handles transport-level TCP/UDP traffic. Gateway Load Balancer inserts network appliances. Classic Load Balancer appears in the slides as the older generation.

Auto Scaling groups

Set minimum, desired, and maximum capacity. An ASG launches or terminates instances and replaces unhealthy members; integration with a load balancer registers targets.

Scaling strategies

Manual changes set capacity directly. Step policies react to thresholds; target tracking maintains a metric target. Scheduled scaling handles known events; predictive scaling forecasts recurring demand.

Check your understandingDoes a load balancer itself add new EC2 instances?

No. It distributes traffic. An Auto Scaling group adds, removes, and replaces instances.

Amazon S3

Store objects and choose access, protection, and lifecycle policies.

↑
Buckets and objects

A bucket belongs to a Region. Objects have a key, content, metadata, optional tags, and optional version ID. Prefixes resemble folders but form part of the object key. Bucket naming rules depend on the bucket type and namespace.

Uploads and uses

S3 supports backups, media, data lakes, software distribution, and static content. Multipart uploads split large objects into parts. Object storage is different from a mounted block device or shared file system.

Permissions

IAM policies govern identities; bucket policies govern resource access, including cross-account access. Block Public Access helps prevent unintended exposure. ACLs are an older access-control mechanism; evaluate explicit denies and all applicable controls.

Static websites

S3 can serve static website content. Website endpoints have different access and HTTPS characteristics from the S3 REST endpoint; CloudFront can provide HTTPS delivery with an appropriately configured origin.

Versioning and replication

Versioning preserves object revisions and helps recover from accidental changes or deletes. SRR copies within a Region; CRR copies across Regions. Replication is asynchronous and requires versioning and appropriate permissions; existing objects need separate handling.

Durability versus availability

Durability is resistance to data loss; availability is the ability to access data when needed. One-Zone classes concentrate data in one AZ, so they carry a different failure risk from multi-AZ storage.

Standard and IA

Standard fits frequent reads. Standard-IA fits infrequent access with rapid retrieval. One Zone-IA fits recreatable or secondary data where a single-AZ risk is acceptable. Include retrieval and minimum-duration costs in comparisons.

Glacier classes

Instant Retrieval supports immediate access to rarely read data. Flexible Retrieval trades restore delay for archive economics. Deep Archive fits long retention and the longest restore tolerance. An archived object may require restoration before access.

Intelligent-Tiering and lifecycle

Intelligent-Tiering responds to changing access patterns. Lifecycle rules implement transitions or expiration based on configured conditions. Account for monitoring, request, transition, and retrieval costs instead of storage price alone.

Express One Zone

Designed for low-latency workloads using directory buckets in a single AZ. Co-locating compute and storage reduces latency; single-AZ placement is an explicit design choice.

Encryption and access analysis

Server-side encryption protects stored objects; client-side encryption happens before upload. IAM Access Analyzer identifies unintended sharing. Customers still control data access, retention, and configuration.

Storage Gateway

Connect on-premises storage workflows to AWS with file, volume, or tape gateway patterns. It bridges existing systems to cloud storage instead of requiring every application to use the S3 API directly.

Check your understandingIs S3 replication the same as CloudFront caching?

No. Replication creates copies in selected buckets. CloudFront caches responses near users for delivery.

Databases & analytics

Start with the data model and access pattern.

↑
Relational and NoSQL

Relational databases use structured tables and SQL relationships. NoSQL systems specialize in key-value, document, graph, or other access patterns with different schema and scaling tradeoffs. JSON is a data representation, not a database.

RDS and Aurora

RDS manages relational database operations such as backups and patching. Aurora is AWS’s MySQL/PostgreSQL-compatible database family; Aurora Serverless adjusts capacity to demand. Managed databases reduce host administration, but you still configure data access and protection.

Replicas and failover

Read replicas scale reads; a traditional Multi-AZ standby supports availability and failover. Cross-Region replicas can support disaster recovery and nearby reads. Deployment modes have different read and replication capabilities; do not treat every replica as equivalent.

ElastiCache

Managed in-memory caching reduces database load and accelerates repeated reads or session access. Cache invalidation and fallback behavior remain application concerns.

DynamoDB and DAX

DynamoDB is a managed serverless key-value/document database. Global Tables support multi-Region access. DAX is a cache specifically for DynamoDB, unlike a general-purpose ElastiCache deployment.

Redshift

A data warehouse for analytical SQL (OLAP), rather than a typical transactional database (OLTP). Column-oriented processing suits large aggregations; the slides cover provisioned and serverless operation.

EMR

Run big-data frameworks such as Spark and Hadoop for distributed processing. Choose it when the workload needs those processing ecosystems.

Athena and QuickSight

Athena queries S3 data using SQL without managing query servers. QuickSight turns datasets into business dashboards. Efficient formats, compression, and limited scans reduce analytical work.

DocumentDB, Neptune, and Timestream

DocumentDB supports MongoDB-compatible document workloads; Neptune models highly connected graphs; Timestream targets time-series data. Select by the access pattern rather than the familiar product name alone.

Managed Blockchain

Supports blockchain use cases involving shared transaction records and network participants. The slides introduce Hyperledger Fabric and Ethereum use cases.

Glue

A managed data integration and ETL service. The Data Catalog records dataset metadata that analytical services can use; ETL extracts, transforms, and loads data.

Database Migration Service

DMS migrates and replicates database data, including changes during migration. Same-engine and cross-engine migrations differ; schema conversion and application compatibility require planning.

Check your understandingYou need SQL queries over log files already stored in S3. Which service fits?

Athena. Use QuickSight to visualize results; Redshift is the warehouse choice, and EMR runs big-data frameworks.

Other compute services

Choose the right level of control for your application.

↑
Containers and images

Containers package application code and dependencies while sharing the host kernel. Virtual machines include a guest OS. Image architecture and OS compatibility still matter. Registries store images; they do not run the workload.

ECS and ECR

ECS schedules and manages containers. With EC2-backed capacity, you operate the hosts. ECR stores container images that workloads can pull.

Fargate and EKS

Fargate runs supported container workloads without managing EC2 hosts. EKS provides managed Kubernetes orchestration; Kubernetes and Fargate solve different layers of the stack.

Serverless

Servers still exist, but provisioning and maintaining them is handled by the provider. The concept extends beyond functions to services such as managed storage, messaging, and databases.

Lambda

Run short-lived, event-driven functions. Pay depends on invocation and allocated compute duration. The slides discuss supported runtimes, custom runtimes, compatible container images, and the execution time limit. Generic long-running containers fit a container service better.

Event-driven examples

An S3 upload can invoke a function to create a thumbnail and store metadata in DynamoDB. EventBridge can trigger scheduled work. Give the function an execution role with only required permissions.

API Gateway

Publish and manage HTTP/REST or WebSocket APIs, including authorization, throttling, and monitoring. A common serverless API connects API Gateway to Lambda and DynamoDB.

Batch

Queue and schedule finite computing jobs on appropriate capacity. Useful for processing that exceeds a short function’s constraints; package the workload and let Batch coordinate execution.

Lightsail

Simplified infrastructure bundles for small websites, applications, and development environments. It reduces setup choices compared with assembling a full EC2-based architecture.

Check your understandingWhich service stores images, and which runs containers without managing hosts?

ECR stores images. Fargate supplies managed container compute; ECS or EKS handles orchestration.

Deploying & managing infrastructure

Make infrastructure and releases repeatable.

↑
CloudFormation

Declare infrastructure in templates, then manage it as a stack. Repeatable definitions, dependency handling, reviewable changes, and consistent environments reduce manual configuration drift.

CDK and Infrastructure Composer

CDK expresses infrastructure with programming languages and synthesizes CloudFormation templates. Infrastructure Composer visually assembles and inspects infrastructure definitions.

Three-tier application

A load balancer fronts application instances, which use a database and possibly a cache. Place redundant components across AZs and give each tier only its required network access.

Elastic Beanstalk

Deploy application code onto a managed application platform that configures resources such as EC2, load balancing, and scaling. You retain configuration choices and pay for the underlying resources. Single-instance, web, and worker patterns serve different needs.

CodeCommit

The source-control service presented in the slides: private Git repositories with version history and collaboration. It occupies the source stage of a pipeline.

CodeBuild and CodeArtifact

CodeBuild compiles and tests code, producing build outputs. CodeArtifact stores software packages and dependencies used by tools such as npm, pip, and Maven.

CodeDeploy and CodePipeline

CodeDeploy automates application rollouts to supported targets, including servers. CodePipeline connects source, build, test, and deploy stages; it is the coordinator rather than the compiler.

Systems Manager

Manage fleets of AWS and on-premises machines with commands, inventory, patching, and automation. Managed-node access depends on agent setup, IAM permissions, and connectivity.

Session Manager and Parameter Store

Session Manager provides controlled shell access without opening inbound SSH. Parameter Store holds versioned configuration and encrypted values with IAM access control. Configure session logging and secret access deliberately.

Check your understandingHow do CDK and CloudFormation relate?

CDK code synthesizes a CloudFormation template; CloudFormation then provisions and manages the resources.

Global infrastructure

Route users to nearby, healthy applications.

↑
Reasons to go global

Reduce user latency, provide recovery options across Regions, and avoid concentrating all capacity in one location. Multi-Region operation adds data consistency, cost, and operations complexity.

Route 53 records

DNS maps names to destinations. A resolves IPv4, AAAA resolves IPv6, CNAME points to another hostname, and alias records target supported AWS resources.

Routing policies

Simple routing gives a basic answer; weighted routing splits traffic by weights; latency routing selects a suitable Region; failover routing uses health checks and a standby. Routing is not the same as copying application data.

CloudFront

A CDN caches responses at edge locations. Origins can include S3 and application endpoints. Origin Access Control can protect an S3 origin; a website endpoint behaves differently from an S3 REST origin.

Caching versus replication

CloudFront caches according to cache policy and freshness settings. S3 cross-Region replication creates copies in configured destination buckets. Choose based on delivery versus durable replication needs.

S3 Transfer Acceleration

Uses edge entry points and the AWS network to accelerate eligible long-distance S3 transfers. It changes the transfer path, not the bucket’s Region.

Global Accelerator

Routes traffic over the AWS global network to regional application endpoints using static anycast IPs. It does not cache content; it suits network performance and endpoint failover requirements.

Outposts, Wavelength, and Local Zones

Outposts extends AWS infrastructure into your premises; you handle local physical security. Wavelength places compute near carrier networks. Local Zones place selected AWS resources near population centers outside a Region’s main AZ footprint.

Availability patterns

Single-AZ is the simplest but most concentrated. Multi-AZ improves regional resilience. Multi-Region active-passive provides a recovery environment; active-active serves from multiple Regions and needs careful state management.

Check your understandingGlobal Accelerator or CloudFront for cached images at the edge?

CloudFront. Global Accelerator improves the network path to applications without caching responses.

Cloud integration

Decouple producers and consumers so each can scale independently.

↑
Synchronous versus asynchronous

A synchronous caller waits for a response. Asynchronous messaging buffers work, handles bursts, and reduces direct dependencies. Design for retries, failures, and duplicate processing.

SQS Standard

A managed queue distributes work among consumers. Messages are retained until deletion or expiry; consumers delete successfully processed messages. At-least-once delivery means handlers should tolerate duplicates.

SQS FIFO

Use ordered message groups and deduplication when ordering matters. FIFO does not remove the need for application-level error handling and safe retries.

SNS

Publish to a topic and deliver to subscribers such as queues, functions, HTTP endpoints, or notification channels. Fan-out sends an event to multiple interested consumers rather than sharing a queue’s work.

Kinesis Data Streams and Data Firehose

Kinesis ingests streaming records for real-time consumers and analysis. Data Firehose delivers streaming data to destinations such as S3 and analytical services.

Amazon MQ

Managed ActiveMQ or RabbitMQ brokers support existing messaging protocols and applications. It fits broker-compatible migrations, whereas SQS and SNS are cloud-native queue and pub/sub choices.

Check your understandingA single order must notify billing and shipping independently. What pattern fits?

Publish to SNS and subscribe separate SQS queues, so billing and shipping each receive and buffer their own work.

Cloud monitoring

Distinguish measurements, audit history, traces, and service health.

↑
CloudWatch metrics

Time-series measurements describe resource behavior. Dashboards visualize them; custom metrics cover application-specific signals. EC2 memory and guest OS logs require appropriate collection rather than relying on default instance metrics.

Alarms

Evaluate metrics and move between OK, ALARM, and INSUFFICIENT_DATA. Actions can notify SNS, invoke supported EC2 operations, or drive scaling. Missing data is not necessarily a healthy system.

Logs and agents

Collect application and system logs, configure retention, and grant permissions. An agent on EC2 or on-premises hosts can send logs and additional metrics.

EventBridge

Route service, application, or partner events to targets using rules. Scheduled events trigger periodic work. Event buses, schemas, archive, and replay support event-driven integration.

CloudTrail

Audit account activity and API calls from console, CLI, SDKs, and services. Use it to investigate who changed or deleted a resource. Configure the needed event types and durable trail storage; default event history is not a complete permanent audit archive.

X-Ray

Trace a request across distributed components to identify dependencies, errors, and latency bottlenecks. Instrumentation provides context beyond separate log lines.

AWS Health

The public service view reports broad AWS service events; the account view highlights events relevant to your resources, including planned changes and remediation guidance.

Check your understandingAn administrator deleted a resource. Which tool should you inspect first?

CloudTrail for the API event and identity. CloudWatch measures operational behavior; X-Ray traces application requests.

Amazon VPC

Control network boundaries and traffic paths.

↑
Addresses and scope

A VPC is regional; each subnet belongs to one AZ. CIDR blocks define address ranges. Public IPv4 reaches the internet, private addresses serve private networks, and an Elastic IP provides a persistent public IPv4 allocation.

Routes and internet access

Route tables select destinations and next hops. An internet gateway connects a VPC to the internet. A public route alone does not make every instance reachable; addresses and security controls also matter.

NAT

A public NAT gateway allows private-subnet workloads to initiate outbound IPv4 internet connections without accepting unsolicited inbound connections. It needs an appropriate public-subnet route; a NAT instance is the self-managed alternative.

Security groups versus NACLs

Security groups are stateful allow controls on interfaces. Network ACLs are stateless subnet controls with allow and deny rules; return traffic must be allowed explicitly. Rules and association scope are frequent comparison points.

Flow Logs

Record IP traffic metadata for interfaces, subnets, or VPCs. Useful for investigating accepted or rejected traffic; flow logs are not packet-content captures.

Peering

Connect two VPCs using private networking and non-overlapping address ranges. Peering is non-transitive: A-to-B and B-to-C do not automatically provide A-to-C connectivity.

Endpoints and PrivateLink

VPC endpoints reach supported services privately. Gateway endpoints support S3 and DynamoDB; interface endpoints use private interfaces and PrivateLink. PrivateLink can expose a service without connecting entire networks.

VPN connections

Site-to-Site VPN connects a remote network through encrypted tunnels over the internet. A customer gateway represents the on-premises side. Client VPN provides user-device access to private networks.

Direct Connect

A dedicated network connection to AWS gives a private connectivity path. Private does not automatically mean encrypted; evaluate encryption separately.

Transit Gateway

A central hub connects VPCs and on-premises networks, simplifying large topologies and supporting transitive routing when configured.

Check your understandingDoes VPC peering through an intermediate VPC automatically provide transit?

No. Peering is non-transitive. Use explicit connections or a routing hub such as Transit Gateway.

Security & compliance

Protect, detect, investigate, and demonstrate compliance.

↑
Shared responsibility in practice

For EC2, customers patch the guest OS; with RDS, AWS handles the underlying host. Customers still control identities, database permissions, network access, and data protection. In S3, bucket policies and data configuration remain customer responsibilities.

Shield and WAF

Shield addresses distributed denial-of-service attacks. WAF filters HTTP requests using web ACL rules, such as IP, rate, or request-content conditions. These complement network access controls rather than replacing them.

Network Firewall and Firewall Manager

Network Firewall inspects traffic through configured VPC paths. Firewall Manager centrally applies supported security policies across an organization’s accounts and resources.

Encryption states

At-rest encryption protects stored data; in-transit encryption protects network transfers. TLS and key management address different pieces of the protection model.

KMS and CloudHSM

KMS manages keys and cryptographic operations with AWS integrations. Distinguish customer-managed, AWS-managed, and AWS-owned keys. CloudHSM supplies dedicated hardware security modules with more customer control over key management.

ACM and Secrets Manager

Certificate Manager provisions and manages TLS certificates for supported uses. Secrets Manager stores secrets and supports rotation workflows; Parameter Store is also used for configuration and encrypted parameters.

Artifact

Access AWS compliance reports and agreements. An AWS certification or report does not automatically make your workload compliant; configuration and business processes still matter.

GuardDuty

Detect suspicious activity from supported AWS telemetry, such as API, network, and DNS signals. Findings can trigger investigation or automated response.

Inspector and Macie

Inspector assesses supported compute and software workloads for vulnerabilities and exposure. Macie discovers sensitive data in S3. Threat detection, vulnerability assessment, and sensitive-data discovery are separate tasks.

Config

Record resource configuration and changes; evaluate compliance against rules. It answers how a resource was configured and whether it meets a rule, rather than simply identifying who called an API.

Security Hub and Detective

Security Hub aggregates security findings and posture information. Detective supports investigation of related activity to understand potential incidents.

Access Analyzer and root tasks

Access Analyzer helps identify unintended access. Protect root credentials and restrict root usage to required tasks; use scoped identities for daily operations.

Testing and abuse reporting

Security tests must follow AWS’s applicable testing policy and scope. The slides distinguish permitted assessments from prohibited disruptive activity and discuss reporting abuse. Check the policy before conducting a real test.

Check your understandingWhich service finds sensitive data in S3: Inspector, GuardDuty, or Macie?

Macie. Inspector looks for vulnerabilities; GuardDuty looks for suspicious activity and threats.

Machine learning

Match the input and desired output to the service.

↑
Rekognition

Analyze images and video for objects, scenes, and supported visual recognition tasks. Choose it for visual content rather than document-table extraction.

Transcribe and Polly

Transcribe converts speech into text, such as captions. Polly converts written text into synthesized speech.

Translate and Comprehend

Translate converts between languages. Comprehend extracts language insights, such as entities, sentiment, and key phrases.

Lex and Connect

Lex builds conversational interfaces with speech and text. Connect provides a cloud contact center; bots and contact-center workflows can work together.

SageMaker AI

Tools for preparing data and building, training, and deploying machine-learning models. Use it when creating a model workflow instead of simply calling a prebuilt AI feature.

Kendra

Enterprise search using machine learning to retrieve relevant information from documents and other sources.

Personalize

Build recommendations based on user and item interactions, such as suggested media or products.

Textract

Extract printed text, handwriting, forms, and tables from documents. It goes beyond simply labeling an image.

Check your understandingYou need fields and tables from scanned invoices. Which service fits?

Textract. Transcribe processes speech; Rekognition analyzes visual content.

Section 16 · PDF pp. 368–416

Account management, billing & support

Organize accounts, attribute costs, and choose the right cost tool.

↑
Organizations and OUs

Manage multiple accounts with a management account and organizational units. Separate environments, teams, security boundaries, and logs where appropriate. Consolidated billing combines eligible usage and discounts.

Service control policies

SCPs set permission boundaries for member accounts; they do not grant permissions. IAM must still allow the action. The management account and service-linked roles have special treatment.

Control Tower

Sets up and governs a multi-account environment using established controls and Organizations. It helps standardize account provisioning and ongoing oversight.

RAM and Service Catalog

Resource Access Manager shares supported resources across accounts. Service Catalog publishes approved products for self-service deployment. Sharing a resource and approving a deployment template solve different problems.

Pricing dimensions

Compute configuration and duration, provisioned storage and performance, requests, retrieval, transfer, and deployment topology affect cost. A cheap storage rate does not guarantee the cheapest total workload.

Commitments and discounts

On-demand usage preserves flexibility; reservations and Savings Plans exchange commitment for discounts; volume pricing rewards eligible usage. EC2 Instance, Compute, and machine-learning savings options differ in scope.

Free offers and support plans

The deck describes Free/Paid account plans and Basic, Business Support+, Enterprise, and Unified Operations support. Offers, eligibility, response commitments, and prices change; verify them before buying. A Technical Account Manager is a named support role, not an IAM identity feature.

Pricing Calculator and Billing Dashboard

Calculator estimates a planned architecture. The billing dashboard summarizes incurred charges and account billing information.

Tags and cost reports

Activate suitable cost-allocation tags to attribute costs. Cost and Usage Reports provide detailed line items for analysis. Resource Groups organize resources using shared criteria such as tags.

Cost Explorer

Explore historical spend, compare usage patterns, forecast costs, and examine commitment opportunities. It analyzes usage already recorded, rather than only estimating a hypothetical design.

Budgets and billing alarms

Budgets track actual or forecast spending and other targets with notifications or configured actions. CloudWatch billing alarms monitor estimated charges through the billing metric in us-east-1. An alert alone does not cap spending.

Anomaly detection and quotas

Cost Anomaly Detection identifies unusual spending patterns. Service Quotas tracks limits and supports increase requests; quota alarms are about capacity limits, not budget enforcement.

Compute Optimizer and Trusted Advisor

Compute Optimizer uses utilization data for sizing suggestions. Trusted Advisor checks broader account practices such as security, resilience, cost, performance, service limits, and operations. Review recommendations in workload context.

Account hygiene

Centralize audit logs, use MFA and least privilege, tag consistently, monitor configuration, and select support suited to the workload. Keep credentials and recovery processes under review.

Check your understandingEstimate a future design, explore past spend, or alert on a forecast overrun?

Use Pricing Calculator, Cost Explorer, and AWS Budgets respectively. They answer three different cost questions.

Advanced identity

Separate workforce access, application users, and temporary credentials.

↑
STS

Security Token Service issues temporary, limited-duration AWS credentials. Role assumption supports service access, federation, and cross-account workflows without distributing long-lived keys.

Cognito

Provide sign-up and sign-in for web and mobile application users, including federation with supported identity providers. These customers do not each need an IAM user.

Active Directory

A directory centralizes users, computers, groups, and related organizational objects. It can underpin authentication and access management for existing enterprise workloads.

Directory Service options

Managed Microsoft AD hosts a managed directory and can establish trusts. AD Connector proxies authentication to an existing directory. Simple AD supplies a smaller AD-compatible directory with different capabilities.

IAM Identity Center

Centralize workforce single sign-on across AWS accounts and business applications. Connect an identity source, then assign access to appropriate users and groups.

Compare scope

IAM controls AWS permissions, Organizations manages accounts, STS issues temporary credentials, Cognito serves app users, and Identity Center centralizes workforce sign-in.

Check your understandingEmployees need one sign-in across several AWS accounts. Which service fits?

IAM Identity Center. Cognito is primarily for users of your web or mobile application.

Other AWS services

Recognize specialist services, migration choices, and recovery strategies.

↑
WorkSpaces and AppStream 2.0

WorkSpaces provides managed virtual desktops. AppStream 2.0, as named in the slides, streams applications to users. A full desktop and an individual streamed application are different experiences.

IoT Core

Connect devices, exchange messages, and route device data into cloud services. Device identities and message permissions are part of the security model.

AppSync and Amplify

AppSync supports application APIs and real-time data interactions, including GraphQL. Amplify supplies tools and services for building and deploying web/mobile applications with connected backends.

Infrastructure Composer and Device Farm

Composer visually creates infrastructure definitions. Device Farm tests applications on browsers and real mobile devices, producing artifacts such as logs and screenshots.

AWS Backup

Centralize backup plans, schedules, retention, and supported cross-account or cross-Region protection. Verify recovery, not only that a backup job ran.

Recovery strategies

Backup/restore rebuilds after an event. Pilot light keeps core capability running. Warm standby maintains a smaller functional environment. Multi-site keeps active capacity in more than one location. Recovery targets guide the tradeoff.

Elastic Disaster Recovery

Replicates server data into a staging environment and supports recovery into AWS. It is for disaster recovery; Application Migration Service targets migration cutover.

The 7 Rs · retain, retire, relocate

Retain what should stay in place; retire what is no longer needed; relocate a workload environment with minimal application changes. Migration is not always the correct choice.

The 7 Rs · rehost, replatform, repurchase, refactor

Rehost moves an application largely as-is. Replatform makes selected platform improvements. Repurchase changes products, often to SaaS. Refactor/re-architect redesigns the application for new capabilities.

Discovery, Evaluator, and Migration Hub

Application Discovery Service gathers infrastructure and dependency information. Migration Evaluator develops the business case. Migration Hub tracks and coordinates migration activity.

Application Migration Service

MGN supports rehosting physical, virtual, or cloud servers into AWS. It differs from DMS, which moves database data.

Fault Injection Service

The slides call this Fault Injection Simulator (FIS): controlled failure experiments test resilience. Define scope, monitoring, and stop conditions before running an experiment.

Step Functions

Orchestrate workflows with steps, branches, parallel work, retries, and error handling. It coordinates services and can support approval processes.

Ground Station and Pinpoint

Ground Station supports satellite communications and data ingestion. Pinpoint is presented in the deck as a service for segmented customer messaging and campaigns; treat this as a course reference and verify current product availability.

Check your understandingWhich migration strategy changes the application architecture to use cloud-native services?

Refactor/re-architect. Rehost moves it largely unchanged; replatform makes more limited platform improvements.

AWS architecting & ecosystem

Evaluate the whole workload, including how people operate it.

↑
Operational excellence

Run operations as code, make small reversible changes, observe outcomes, and learn from incidents. Use tools such as CloudFormation, CloudWatch, and deployment automation.

Security

Apply least privilege, trace activity, protect data in transit and at rest, automate controls, and practice incident response. Security must span identity, network, application, and operations.

Reliability

Test recovery, automate repair, manage changes, and avoid shared failure points. Multi-AZ designs, backups, health checks, and appropriate capacity help workloads recover.

Performance efficiency

Choose resources for actual access patterns, use managed services where suitable, experiment, and measure. Geographic placement, caching, and specialized services can matter more than a bigger server.

Cost optimization

Attribute spending, reduce idle capacity, match supply to demand, and review commitments. Optimize total business value, including operations effort, rather than only unit price.

Sustainability

Measure impact, maximize useful utilization, reduce waste, and adapt to more efficient technology. Lifecycle policies and right-sized resources can improve both cost and resource use.

General design principles

Treat infrastructure as replaceable, automate repeatable work, loosely couple components, test at realistic scale, and evolve with evidence. Managed services reduce the amount of infrastructure you operate.

Well-Architected Tool and carbon reporting

Use structured workload reviews to identify improvement areas. The Customer Carbon Footprint Tool supports understanding emissions associated with AWS usage.

Cloud Adoption Framework perspectives

Business connects investment to outcomes; People develops skills and culture; Governance manages risk and oversight. Platform builds the foundation; Security protects it; Operations delivers ongoing service.

CAF domains and phases

Transformation can change technology, processes, organization, and products. Progress through Envision, Align, Launch, and Scale to identify value, close capability gaps, prove pilots, and expand.

Right sizing

Match capacity and instance types to measured requirements before and after migration. Revisit decisions as demand changes; a recommendation should be checked against performance and resilience needs.

Marketplace and learning

Marketplace distributes third-party software and solutions. Documentation, whitepapers, Solutions Library, training, Academy, and re:Post support learning and troubleshooting. Community answers are not a substitute for urgent support.

Partners and managed operations

Professional Services and the Partner Network provide expertise for projects and migrations. AWS Managed Services helps operate supported environments. Choose the appropriate relationship for advisory, delivery, or ongoing operations.

Check your understandingHow is CAF different from the Well-Architected Framework?

CAF addresses organizational cloud transformation across six perspectives. Well-Architected reviews workloads across six architecture pillars.
